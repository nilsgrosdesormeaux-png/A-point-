Fiabilise l'import : dates en lettres françaises, milliers, encodage Excel

Le parsing de date dépendait de new Date() pour les dates en toutes
lettres, qui échoue silencieusement sur la plupart des mois français
(août, février, juillet, mai...) et sur le suffixe ordinal ("1er").
Ajout d'un parseur dédié (MOIS_FR + parserDateEnLettresFr) qui couvre
les douze mois, avec ou sans accent, abrégés ou non.

Le parsing de quantité/prix confondait un séparateur de milliers
français ("1.234,50", "1 234") avec un point décimal isolé, produisant
des valeurs jusqu'à 1000 fois trop petites sans aucune erreur visible.
nettoyerNombreRobuste distingue maintenant les deux en comptant les
groupes de chiffres autour de chaque séparateur.

Ajout d'une détection d'encodage (UTF-8 avec repli windows-1252) pour
les CSV exportés depuis Excel, où les caractères accentués produisaient
des caractères de remplacement au lieu d'être lisibles.

Trois nouveaux tests Playwright couvrent ces cas (104 tests, 0 échec).
